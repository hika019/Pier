# Bridge 観察手順

推測で Bridge の挙動を書かない。観察した事実だけを docs に書き、確度を明記する。

## 0. クリーンルームの線引き
- してよい: 画面を見る、操作して結果を記録する、スクリーンショットからピクセル寸法・色値を測る、公開ヘルプ (helpx.adobe.com) を読む。
- してはいけない: Bridge のバイナリ・スクリプト・リソース (アイコン、プリセット、テンプレート、`.BridgeCache` 等の非公開形式) を解析・複製する。スクリーンショットやアイコンをリポジトリにコミットする。
- スクリーンショットは `plan/bridge/<area>/<yyyymmdd>-<what>.png` (gitignore) に置く。

## 1. 観察の単位
1 回の観察 = 1 つの領域 (例: パスバー右端のボタン群、一括リネームダイアログ)。次を記録する:
- Bridge のバージョン (ヘルプ › Bridge について)、OS、UI 言語、テーマの明るさ。
- 部品の順序・ラベル (日本語版と英語版の両方が取れれば両方)・ツールチップ。
- 寸法 (pt)、色 (16 進)。スクリーンショットのスケール係数を明記。
- 挙動: クリック、ダブルクリック、右クリック、ドラッグ、キーボード (修飾キーの組み合わせ)、無効状態になる条件、空状態の表示。
- 永続化: 再起動後に残るか、ワークスペースに保存されるか。

## 2. 記録先
- 観察メモ: `plan/bridge/observed-ui.md` (時系列の生ログ)。
- docs への反映:
  - レイアウト・寸法・色 → `docs/ui-design.md` の該当節 (`要観察` を消して値を書く。トークン表の `要計測` を埋める)。
  - メニュー・ショートカット → `docs/command-catalog.md`。
  - 挙動の仕様 → `docs/requirements.md` の備考。
- 反映した行には観察日とバージョンを括弧で付ける (例: `(観察 2026-11-10, Bridge 16.0.1 macOS)`)。

## 3. 確度
- 実機で確認 → そのまま書く。
- 公開ヘルプのみ → `(ヘルプ記載、実機未確認)` を付ける。
- 確認できない → `要観察` のまま残し、理由を書く。

## 4. 完了報告
①観察した領域 ②docs の変更差分 (ファイルと行) ③残った `要観察` ④ Bridge と Pier の意図的な差 (Adobe サービス依存で対象外など) を報告する。
